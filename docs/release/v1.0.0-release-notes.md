# SellPilot v1.0.0 发布说明

发布日期：待最终发布 PR 合入 `main` 后由发布负责人确认

状态：`READY_FOR_RELEASE`

## 发布概述

v1.0.0 是 SellPilot 课程实训与演示范围内的首个完整交付版本。该版本统一商品、库存、
订单、物流、客服和 AI 运营任务，以 PostgreSQL 保存业务与执行数据，以
`MockShopeeAdapter` 提供稳定、可重复的 Shopee 演示边界。

本次发布不包含真实 Shopee OAuth、真实商品发布或真实客服发送。`v0.5.0` 继续保留为
Assistant Workflow Integration 历史里程碑，不移动或覆盖。

## 核心模块

- 中文聊天式 AI 运营助手；
- 市场数据与智能选品；
- 商品评论分析与产品改良；
- 多语言内容生成和内容版本；
- 商品、SKU、库存、订单与物流；
- 客服会话与知识库检索；
- Task Center、Confirmation 和 OperationLog；
- PostgreSQL Demo 初始化、就绪检查和真实 HTTP E2E Smoke。

## 三条业务闭环

### 产品决策闭环

```text
市场数据 → 智能选品 → 评论分析 → 产品改良 → 改良报告 → 商品草稿
```

智能选品从 PostgreSQL 市场快照自动检索候选，使用确定性规则评分并返回 Top N、风险和
来源；评论分析和产品改良保留证据关联。保存草稿属于写操作，必须经过 Confirmation。

### 商品运营闭环

```text
商品事实 → 多语言内容生成 → 事实检查 → 合规检查
        → 有界 Loop → 草稿 → Confirmation → Mock 操作
```

内容生成从数据库读取商品事实，质量 Loop 最多执行三轮。默认只返回结果，不自动保存或
发布；模拟上架属于 HIGH_RISK。

### 客服闭环

```text
买家消息 → 意图与风险识别 → RAG / 订单 / 物流 Branch
        → 回复草稿 → 人工处理或 Confirmation → Mock 发送 → 审计日志
```

订单和物流回复引用对应 Tool 结果，政策回复引用 RAG 来源；退款、投诉、赔付、地址或订单
修改、低置信度和无可靠依据等情况转人工。普通回复默认也只生成草稿。

## Assistant 与运行时

- `/assistant/plan` 保持只规划、不创建 Task、不调用 Tool 的语义；
- Assistant Task 支持 `create_only` 和 `create_and_run`；
- 10 项 Assistant Capability 由服务端 Registry 映射到唯一 Workflow 与 Tool；
- `TaskRunner` 通过 `WorkflowRegistry` 执行，业务节点通过 `ToolExecutor` 调用；
- Branch 记录实际分支，Loop 有固定上限，错误不会被包装成虚假成功；
- Task、Step、ToolCall、Confirmation 和 OperationLog 使用一致的用户所有权与关联 ID。

## 风险确认与审计

- Tool 按 READ、WRITE、HIGH_RISK 分级；
- 写操作和高风险操作创建 Confirmation，并记录前后快照或审计差异；
- 确认、取消和恢复使用幂等保护，不重复执行；
- Request ID 贯穿 API、任务和日志；
- 公开错误与任务结果经过脱敏和大小限制，不返回密钥、内部 Prompt 或 traceback。

## PostgreSQL、RAG 与演示数据

- 正式本地与 CI 验证使用 PostgreSQL 17；
- 数据库结构由 Alembic 管理，当前 head 为 `20260728_0007`；
- Mock 商业数据包含商品、市场快照、SKU、库存、订单、物流、评论和客服会话；
- 知识元数据保存在 PostgreSQL，向量索引使用 ChromaDB；
- Demo 知识数据已完成可重复导入、全量重建、来源统计、检索命中和无答案拒答验证；
- 由 Mock CSV 生成的知识文档始终标记为 Mock，不作为真实店铺或生产知识数据。

v0.5.0 到 v1.0.0 没有新增数据库迁移。

## Mock 与真实能力边界

当前真实实现包括 PostgreSQL 持久化、Task/Workflow/Tool 运行时、Confirmation、审计、
模型兼容接口和 RAG 检索。Shopee 数据与外部操作仍使用 Mock Adapter。

当前不包含：

- 真实 Shopee OAuth；
- 真实商品发布、更新或上下架；
- 真实客服发送；
- 真实订单、地址、退款或赔付修改；
- 多租户、多店铺生产部署；
- 财务、ERP、生产监控和灾难恢复系统。

`RealShopeeAdapterStub` 缺少真实实现或配置时明确失败，不会回退到 Mock。

## 已知非阻塞限制

- 外部内容模型和 RAG LLM 的鉴权、限流与可用性由供应商决定；离线模板会明确标识；
- Chroma embedding 模型首次冷启动可能明显慢于后续请求；
- 生产构建可能提示大 chunk，但最近一次构建成功；
- 产品决策闭环按受控任务逐步执行，未增加跨域自动 composite workflow；
- 本机未安装 Docker CLI，容器 build/up/health/down 仍需在有 Docker 的环境复核。

## 从 v0.5.0 升级

本次没有新增 Alembic 迁移，但升级后仍应执行迁移一致性检查：

```powershell
cd .\backend
uv sync --frozen
uv run alembic upgrade head
uv run alembic current
uv run alembic check
uv run sellpilot-check-demo-readiness

cd ..\frontend
npm ci
```

现有环境如在 `.env` 中显式设置了 `APP_VERSION`，应同步为 `1.0.0`。新环境按根目录
README 完成 `.env`、管理员、Mock 数据和知识数据初始化。不要覆盖已有 `.env`，不要
清空已有 PostgreSQL。

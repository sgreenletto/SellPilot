# Git 工作流

## 分支定义

- `main`：稳定发布分支。
- `develop`：日常集成分支。
- `feature/<简短功能名>`：新功能开发分支。
- `fix/<简短问题名>`：问题修复分支。
- `docs/<简短文档名>`：文档变更分支。
- `release/v<版本号>`：发布准备分支。

## 分支流程

1. 禁止直接向 `main` 提交业务开发代码。
2. 功能分支从最新的 `develop` 创建。
3. 功能分支通过 Pull Request 合并到 `develop`。
4. 发布版本由 `develop` 合并到 `main`；如需发布准备，可使用 `release/v<版本号>`。
5. 合并前应完成适用的检查、测试、文档更新和评审。

## 提交信息

提交信息使用以下类型前缀：

- `feat:` 新功能
- `fix:` 问题修复
- `docs:` 文档变更
- `refactor:` 不改变外部行为的重构
- `test:` 测试变更
- `chore:` 日常维护
- `build:` 构建系统或依赖变更
- `ci:` 持续集成变更

一个提交只处理一个明确主题。标题应简洁、可追踪，不应混入无关格式化或生成文件。

## 提交边界

不得提交生成物、缓存、虚拟环境、`node_modules`、本地数据库、`.env`、API Key、Token、密码或真实用户数据。提交前应检查暂存内容，并确保日志与示例已脱敏。

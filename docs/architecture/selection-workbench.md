# 智能选品前端工作台

## 范围

`/market/selection` 已由占位页替换为正式智能选品工作台。页面只通过
`frontend/src/api/selection.ts` 调用 `/api/v1/selection`，不读取静态结果数组、不直接
调用 `fetch`，也不访问真实 Shopee。

工作台覆盖：

- 站点、类目、价格、成本、物流成本、最低利润、最低利润率、平台费率、其他成本、重量和风险偏好；
- 正式候选查询、选择和输入边界校验；
- 进入工作台时读取当前用户持久化候选清单；候选清单接口关联商品返回站点。URL 明确指定站点时遵从 URL；侧边栏入口没有站点参数时，自动选择候选数量最多的站点（数量相同时按站点固定顺序），再与价格条件下的可分析商品取交集并自动勾选；
- 候选商品卡片的勾选变更复用 Commerce 候选清单确认任务并写回后端，使市场数据页和智能选品页共享同一候选状态；结果区的对比勾选保持为独立的临时状态；
- 市场数据页交接的首个商品类目不限制整份清单；用户手动调整后不再被刷新覆盖；
- 排名、总分、数据完整度、数据来源、利润与七项评分；
- 结构化解释、证据和风险提示；
- 详情抽屉、2–4 项结果对比；
- 后端结构化 JSON 导出数据，并在前端整理为面向运营人员的中文 Markdown 报告；
- 加载、空数据、接口错误、超时、未认证和“后端未连接”状态。

## 状态策略

站点、类目、价格、成本和风险偏好等可复现筛选条件写入 URL query，刷新页面后能够恢复。
候选勾选、分析结果、详情和对比属于短期交互状态，不写入 URL、`localStorage` 或全局 Pinia。
应用壳仅对选品、评论分析、产品改良和内容工坊启用有上限的 Vue `KeepAlive` 缓存，使运行中的
请求及完成结果在站内路由切换后仍可见；浏览器刷新后仍以 PostgreSQL 中的任务、候选清单和内容
版本为事实来源，不把大型分析结果长期复制到浏览器存储。

## 计算边界

成本与物流覆盖值会进入后端确定性利润公式。风险偏好对应版本化评分权重：

- `conservative`：提高利润、物流与售后权重；
- `balanced`：使用 `selection-v1.0.0` 默认权重；
- `growth`：提高需求和竞争权重。

商品重量会透明保存进分析任务条件。当前 Mock 数据没有重量运费阶梯，因此页面明确说明重量
暂不改变评分，不用硬编码系数伪造影响。

## 响应式和可访问性

- 桌面端采用条件栏与结果区双列；
- `<1100px` 改为单列，条件栏取消 sticky；
- 桌面双列布局中，分析条件和候选/结果分别独立纵向滚动，避免长表单带动结果区；
- `<768px` 表单、候选和指标改为单列，抽屉占满可视区域；
- 选择项使用原生 checkbox，按钮和关闭控件具有文字或 `aria-label`；
- 状态同时使用文字、图标和结构表达，不只依赖颜色。

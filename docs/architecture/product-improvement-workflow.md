# 产品改良报告与确认草稿闭环

评论分析结果先由确定性证据规则限定可改良类别：只有低评分或含明确缺点表达的评论才能进入
产品改良。启用 `aliyun_bailian` 时，百炼模型根据这些限定类别及原文生成标题和可执行方案；
模型输出必须通过结构化 Schema 校验，且类别集合必须与输入完全一致，不能新增“描述不符”等
无证据问题。未配置模型时才使用离线规则文案。没有改进信号时返回空报告，不凭空生成问题。
为兼容旧分析结果，产品改良服务会再次排除“delivery took the usual time / 配送时效正常”等
明确正常的物流表达；仅谈及物流不等于存在物流问题。
频率、严重度和优先级仍由持久化证据确定，LLM 不参与证据计数或类别判定。
频率、严重度、优先级、置信度和证据评论编号在前端以紧凑依据区展示，并写入面向工厂的
Markdown 报告，便于人工复核；这些指标不替代商品事实、成本与工厂可行性核验。
其中结论置信度衡量“该分类足以支撑这条改良建议”的可靠程度：评论判定平均置信度占
60%，证据充足度占 25%（3 条不同评论达到满分），问题覆盖率占 15%（覆盖 20% 有效评论
达到满分）。频率和证据数均按主题与评论 ID 去重，严重度按证据评论星级计算。
报告算法版本升级后不会复用旧算法报告，而是为同一分析生成递增的新版本。用户每次从评论分析页
主动点击“生成产品改良报告”也会强制创建递增的新版本，避免把旧报告误认为本次重新生成结果。

```text
ReviewAnalysisResult / Evidence
→ ProductImprovementService
→ ProductImprovementReport / Suggestion
→ 人工编辑、采纳或忽略
→ ConfirmationTask(PENDING)
→ 用户明确确认
→ ProductContent / ProductContentVersion(DRAFT)
```

创建草稿请求只创建内部 AgentTask 和待确认任务。确认执行器才写商品内容草稿；不发布商品、不改价格或库存，
重复确认由公共确认状态机保证不会重复执行。内部报告与接口保持结构化 Schema，面向用户的下载格式为
Markdown，由浏览器下载，服务器不写本地文件。

用户在产品改良页内完成唯一一次明确确认即可，不需要再进入任务中心操作。任务中心中的同一条
AgentTask / ConfirmationTask 只承担状态追踪和审计留痕，不是草稿存储位置，也不是创建流程的
必经页面。确认成功后，草稿保存在 `ProductContent` 与 `ProductContentVersion(DRAFT)`，并在产品改良页
直接展开已采纳建议、改良方案和 Mock 边界。该草稿是面向运营与工厂的待审核改良方案，不冒充完整的
多语言商品文案，因此不要求跳转内容工坊。产品改良页同时始终提供“返回评论分析”入口，不依赖报告是否为空。
改良方案内容容器使用语言中立标记 `und`，与内容工坊的 `en`、`zh-CN` 等发布语言版本隔离。

草稿创建后仍属于产品改良模块。页面按来源商品查询 `improvement_draft` 与
`improvement_revision` 版本，支持查看全部历史版本和编辑最新版本。编辑保存流程为：

```text
读取最新草稿版本
→ 人工编辑结构化改良项
→ 携带 expected_version 创建待确认任务
→ 用户明确确认
→ 再次校验最新版本
→ 追加 ProductContentVersion，不覆盖旧版本
```

旧版本只读保留。并发期间若出现更新版本，确认执行器拒绝写入并要求重新加载，防止覆盖其他修改。
草稿列表由 PostgreSQL 恢复，不使用 `localStorage` 充当事实来源。

页面只查询当前报告 `source_product_id` 对应的改良草稿。由于一个商品可能存在不同站点或历史内容
容器，用户看到的 `sequence` 独立于容器物理版本号，按商品全部改良草稿的创建顺序递增。清空历史
同样属于写操作：确认后追加 `improvement_history_cleared` 审计标记，列表隐藏标记以前的版本；
底层版本不删除，但展示序号以最近一次清空标记为分界重新计数，新草稿从 `v1` 开始。

产品改良页使用评论分析 ID 恢复已持久化报告，并记住“评论与产品改良”模块最后访问的
子页面；用户离开模块后再次从侧栏进入时回到上次的评论分析页或改良报告页。建议证据区
通过评论证据 API 分页读取、按评论 ID 去重，向用户展示星级、原文和已有中文译文，评论
编号只作为内部关联键。

首版保持单用户、单 Mock Shopee 店铺边界。工厂建议仅是依据模拟评论的运营建议，实施前必须人工核对商品事实、
成本和工厂可行性。

# 评论分析工作台

```text
ReviewAnalysisView
→ review-analysis API client
→ unified HTTP client
→ Step 6 ReviewAnalysis API
```

View 不直接调用 `fetch` 或创建 ECharts。趋势图由 `ReviewTrendChart` 封装并在卸载时
释放实例，筛选、进度、错误、空数据和证据分页均使用后端真实状态。

智能选品结果通过 `/market/reviews?source=selection&product_id=...&site=...` 进入本页。
页面校验并带入商品编号与站点、清除不同商品的旧分析结果，再自动加载对应评论列表；
是否执行分析仍由用户点击决定。显式选品入口优先于评论模块保存的上次产品改良路由，
避免用户被重定向到与当前商品无关的历史报告。

页面覆盖评论原文和已有翻译、情感分类、评论主题、高频痛点、改进信号、时间与站点
趋势、代表评论及点击定位。情感、主题和痛点放在紧凑的分析摘要中，主题只表示评论
谈到了什么，不作为产品问题判断。后台任务步骤只用于诊断，不作为常驻业务面板；同一
评论命中的多个改进证据按评论 ID 合并展示。只有多个时间点时才显示趋势区。

页面将内部 `negative` 统计解释为“含改进信号”：它包含 1—2 星低评分，也包含带明确
缺点表达的 3 星混合评价，不把整条混合评价简单称为差评。只有一个统计周期时不重复展示
趋势区；两个及以上周期才呈现趋势比较。

改进信号作为评论级状态单独展示，不把主题标签误写成缺陷结论。前端会抑制旧分析中与
“符合描述、与图片一致”等明确正向事实冲突的历史“描述不符”标签。
评论列表支持在原文和中文译文中执行同一关键词检索；关键词会同时传入评论分析请求，
保证页面看到的检索范围与实际分析范围一致。

评论主题筛选固定为产品、包装、文案、物流、服务和其他。材料、尺寸规格、错发漏发等
细节归入产品；只有五个业务分类均未命中时才使用其他。高频痛点只展示至少两条评论且
覆盖不少于有效评论数 10%（向上取整）的改进信号，所有标签使用中文。

# 智能选品确定性计算内核

## 状态与范围

本文记录 Step 2 已实现的智能选品纯计算内核。它可以在不调用 LLM、数据库、API、
平台适配器或外部网络的情况下，对经过校验的候选商品稳定计算利润、分项得分、总分、
排名、数据完整度、置信度、推荐事实和风险提示。

当前没有实现候选数据查询、任务编排、结果持久化、Tool、API、自然语言解释或前端页面；
这些能力属于后续步骤。输入仍应由后续应用层通过统一市场数据实体或
`PlatformAdapter` 获取，计算内核不直接读取 CSV，也不依赖 `MockShopeeAdapter`。

## 代码边界

```text
sellpilot/domain/selection/
├── models.py   # 输入、配置、证据和输出 Schema
└── scoring.py  # Decimal 利润、归一化、评分、过滤和排序
```

公开入口：

- `calculate_profit(candidate, config)`
- `score_candidates(candidates, criteria, config)`
- `DEFAULT_SELECTION_CONFIG`

输入必须携带 `source_type` 和 `is_mock_data`，确保后续结果可以保留数据来源及模拟数据标识。

## 公式版本

默认公式版本为 `selection-v1.0.0`。权重和所有会改变结果的常量集中在
`SelectionFormulaConfig` 中，不散落在路由、服务或页面。

| 指标 | 权重 |
| --- | ---: |
| 需求热度 | 0.25 |
| 竞争机会 | 0.15 |
| 利润空间 | 0.25 |
| 评论质量 | 0.12 |
| 物流机会 | 0.08 |
| 售后机会 | 0.08 |
| 工厂适配 | 0.07 |

配置要求七个已知指标完整出现、权重非负且使用 `Decimal` 精确合计为 `1`。未知指标、
错误权重和不合法增长率上下界都会被拒绝。

## 利润计算

所有金额、费率、得分和比较均使用 `Decimal`。金额按 `0.01` 使用
`ROUND_HALF_UP` 舍入，比例按 `0.0001` 舍入。

```text
平台费用 = 售价 × 平台费率
总成本 = 商品成本 + 物流成本 + 平台费用 + 其他成本
利润 = 售价 - 总成本
利润率 = 利润 ÷ 售价
```

售价必须大于 0，成本、物流成本、其他成本不得为负，平台费率必须处于 `[0, 1]`。
最低利润和最低利润率采用包含边界规则：等于阈值时保留，低于阈值时进入 `excluded`，
并保存实际值、阈值和排除原因。

## 归一化与分项得分

候选商品按 `(site, currency)` 建立独立 cohort。一个 cohort 的极值不会改变其他站点
或币种的得分，未进行汇率换算时不得把不同币种的金额解释为可直接比较。

```text
正向分 = (当前值 - 最小值) ÷ (最大值 - 最小值) × 100
反向分 = 100 - 正向分
```

单候选或全部取值相等时明确返回中性分 `50`。得分始终限制在 `[0, 100]`。增长率在
归一化前按版本化上下界 `[-1, 2]` 截断。

- 需求热度：可用的销量、搜索指数、销售指数、增长率分别归一化后取等权平均；
- 竞争机会：竞争指数反向归一化；
- 利润空间：利润率在 cohort 内正向归一化；
- 评论质量：评分固定映射占 80%，评论量 cohort 归一化占 20%；
- 物流机会：`100 × (1 - 物流风险率)`；
- 售后机会：`100 × (1 - 售后率)`；
- 工厂适配：`100 × 工厂适配代理分`。

`competition_index`、物流风险率、售后率和工厂适配代理分由上游数据服务提供。本内核
不会从订单、物流或退货 CSV 自行推测关联关系。

## 缺失值、完整度与置信度

缺失值不会静默转换成 0。缺失分项的分数为 `None`，证据记录 `missing_reason` 和实际
输入；总分只在可用指标之间按原配置权重重新归一；风险提示逐项列出缺失维度。

```text
完整度 = 可计算评分维度数 ÷ 7
置信度 = 完整度 × 可用指标原始权重之和
有效权重 = 配置权重 ÷ 所有可用指标配置权重之和
总分 = Σ(分项得分 × 有效权重)
```

缺少评论、物流、售后或工厂信息的候选仍可计算，但不会获得与完整数据相同的置信度。

## 排名与解释

排序固定使用总分降序、完整度降序，最后按站点、币种和 `product_id` 字典序打破并列。
`rank` 是任务内唯一稳定序号，满足 Step 1 结果表的唯一约束；`cohort_rank` 是站点和
币种组内排名。跨 cohort 的 `rank` 仅用于稳定展示和持久化顺序，不能替代汇率换算后的
商业比较。

推荐内容只由已计算事实生成，包含总分、利润、利润率和最强可用指标。LLM 不参与计算，
也不能覆盖任何分数。

## 异常与边界

- 空候选列表返回空结果；
- 同一批次重复 `product_id` 会被拒绝；
- 单候选和全相等指标使用中性分；
- 极端值经过有界归一化或增长率截断；
- 负利润默认被最低利润阈值排除；若业务显式允许，仍附带负利润风险；
- `rating` 和 `review_count` 必须同时提供或同时缺失；模拟数据的 `0 分 + 0 条评论`
  明确表示暂无评论，评论质量按缺失处理；
- 输入 Schema 拒绝空 ID、非法评分、负计数、非法风险率和非正售价。

## 后续集成要求

Step 3 必须通过统一市场数据服务或 `PlatformAdapter` 获取候选，将公式版本、证据、来源
和模拟标识写入 Step 1 表。API 路由只做协议转换；自然语言解释只能消费内核事实。后续
如创建商品草稿或执行其他业务写操作，仍必须遵循待确认流程。

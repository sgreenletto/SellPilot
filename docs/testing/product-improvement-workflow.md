# 产品改良测试

- 集成测试覆盖评论分析到报告、唯一评论样本计数、证据绑定、建议采纳、Markdown 导出、
  待确认任务和确认后草稿落库。
- 前端测试覆盖认证请求、从评论分析入口自动加载报告、建议更新失败提示，以及“先采纳、
  再选择、再创建待确认任务、最后明确确认”的草稿流程；大小写不同的确认状态均按契约处理。
- 前端还验证建议展开后展示证据评论原文和译文，不向用户展示仅供内部关联的评论编号。
- 评论分析入口强制生成递增的新报告版本；确认后在产品改良页内展开草稿，不依赖内容工坊。
- 集成测试覆盖按商品恢复草稿历史、最新版本编辑待确认、确认后追加版本和旧版本保留。
- 前端测试覆盖历史列表、最新草稿编辑、结构化编辑内容和保存新版本待确认请求。
- 清空历史必须先确认；清空后列表为空、审计版本保留，新建草稿展示序号从 `v1` 重新开始。
- 正常配送表达在新评论分析和旧分析兼容过滤两层均不得生成物流改良建议。
- 构建验收确保报告页使用统一 API 客户端、`Sp` 组件和语义变量。

登录模块现有模拟 Token 与后端 JWT 的集成问题不属于本功能；使用真实后端签发 JWT 时接口可完整执行。
模型网关测试覆盖：百炼结构化输出可生成证据限定类别的建议，以及模型尝试新增
`description_mismatch` 等无依据类别时必须拒绝整个输出。
